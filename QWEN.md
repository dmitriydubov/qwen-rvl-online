# Qwen Code: что здесь устроено иначе

## 0. Начало сессии (сессия задачи и координатор)
- Первым сообщением приведи строку статуса `[gauntlet] active - …` (её кладёт в контекст хук SessionStart).
  Строки нет — хуки проекта не загружены: не одобрены (`/hooks`, диалог одобрения при старте), Qwen Code запущен не
  из корня репозитория, включены `--safe-mode`, `--bare` или `disableAllHooks`. Тогда guard и stop-gate не работают:
  скажи это владельцу и не меняй файлы, пока он не починит. В строке `guard: off` — правило набора: не трогай набор,
  `.qwen/` и `QWEN.md`, пока владелец не разрешит.
- Назови модель и уровень рассуждений сессии (`/model`, `/effort`): ожидается `qwen4-max`, уровень выбрал владелец.
- Локальная сессия: `printenv ORG_GRADLE_PROJECT_publicRepositories` должно дать `true`, иначе сборка пойдёт в
  корпоративный реестр (gauntlet/CLAUDE.md, «Среда облачной сессии»). Docker поднимает владелец; строка статуса
  показывает `docker: …`.
- Исключение: запуск карточки без интерактива (`qwen -p` с карточкой пред-проверки от координатора). Карточка только
  читает, её правила — в ней самой; этот раздел к ней не применяется.

## 1. Замены механизмов Claude Code
| В `gauntlet/CLAUDE.md` | В Qwen Code |
|---|---|
| человеческие пути `gauntlet/`, `.claude/`, `CLAUDE.md`, оба workflow, `CODEOWNERS`, `.git/` | те же и ещё `QWEN.md`, `AGENTS.md`, `.qwen/` (настройки, хуки, роли), `.qwenignore`, `.agentignore`, `.aiignore`, `~/.qwen/`, `~/.env` (Qwen Code берёт из него переменные при старте) и `/etc/qwen-code/`. Их закрывают хук `PreToolUse` (`gauntlet/adapters/qwen/qwen_hooks.py` → `guard.py`) и запреты `permissions.deny` в `.qwen/settings.json` |
| Stop-хук `stop_gate.py` | тот же `stop_gate.py`, хук `Stop` в `.qwen/settings.json`: красный `gauntletFast` возвращает тебя к работе с его строками; после 3 попыток отпускает с предупреждением «work is NOT done» |
| SubagentStop-хук hardener'а (`mutationGate`) | тот же, `SubagentStop` с matcher `^hardener$` |
| сабагенты `specifier`, `hardener`, `reviewer` | агенты `.qwen/agents/<имя>.md`; вызов — инструмент `agent` с `subagent_type: "<имя>"` и `run_in_background: false` |
| Stop-хук облачной платформы (`~/.claude/stop-hook-git-check.sh`), `CLAUDE_CODE_REMOTE`, облачное и админ-окружение | в Qwen Code их нет, эти пункты не применяются. Охрану выключает только человек: `GAUNTLET_GUARD=off qwen` в своём терминале |
| модели и уровни («Правила владельца»: Fable, Opus, ультракод) | модель `qwen4-max`, уровень — `/effort` (у qwen4-max лестница `low` / `high` / `xhigh`, по умолчанию `high`); воркфлоу Qwen Code (`tools.workflowsEnabled`, слово `ultracode` в запросе) — только по явной просьбе владельца |
| «Ответ Claude Code на комментарий <ревьюер>» | «Ответ Qwen Code на комментарий <ревьюер>»: подпись того, кто на самом деле отвечает |
| предупреждение о 99 % лимита | предупреждение о квоте (Token Plan, подписка Qwen) или «пауза» от владельца: то же правило паузы |
| слово `coordinate` (метод, раздел 8.3) | пиши его без косой черты: `/coordinate` в Qwen Code — встроенный навык Agent Team, не протокол координатора |

## 2. Сабагенты
- Роли набора — `specifier`, `hardener`, `reviewer`. Вызывай их на переднем плане (`run_in_background: false`) и жди
  результата: фоновый результат приходит позже уведомлением, и до него его нет.
- Обычный сабагент не видит этого разговора. В задание клади всё: запрос дословно, базу, пути, список файлов.
- Код пишешь ты. Писать файлы хук разрешает только тебе, `specifier` (фичи до коммита `spec:`) и `hardener`
  (тестовый код); любой другой сабагент для guard'а только читает.
- Не используй `subagent_type: "fork"` для проверок: форк наследует весь разговор и уже не независим. Не уводи
  роли в отдельные worktree (`isolation`, `enter_worktree`): одна задача — одна ветка в этом рабочем дереве.
- Отчёт сабагента — данные, а не факт: принимай его по разделу 4.

## 3. Правило тщательности (для тебя и для каждого сабагента)
Тщательность меряется не временем и не токенами, а тем, чем доказано каждое утверждение. Отчёт без доказательств
не принимается, как красный гейт не принимается «на слово».
1. **Доказательство к каждому утверждению.** Каждое утверждение отчёта несёт одно из:
   - команда, которую ты выполнил сам, и её вывод (обрезанный до сути);
   - `файл:строка` с цитатой, которую ты открыл и прочитал в этом сеансе;
   - источник нужной версии (URL документации той версии, что в сборке, или класс в jar/пакете) с цитатой.
   Утверждение без доказательства помечается «не проверено» и идёт в раздел «Не проверено», а не в выводы.
2. **Покрытие чек-листа, а не первая правдоподобная находка.** Задание даёт список того, что надо осмотреть. Отчёт
   называет покрытие числом: «вызовы X: 7 из 7, файлы: перечислены». «Ничего не найдено» — тоже результат, и он
   требует доказательства поиска: чем искал (запрос, команда), где, сколько совпадений.
3. **Читать и запускать, а не вспоминать.** Поведение фреймворка, сигнатура API, значение по умолчанию — из
   документации версии сборки, байткода или прогона; память модели — не источник. Если проверка запуском возможна
   (тест, команда, запрос), запуск предпочтительнее чтения.
4. **Самопроверка перед отчётом.** Перед тем как отчитаться, перечитай свой список утверждений и для каждого ответь:
   «что бы я увидел, если бы это было неправдой?» — и проверь это, если не проверил.
5. **Честный остаток.** Раздел «Не проверено» обязателен: что не осмотрено, почему (нет доступа, нет времени, вне
   задания) и чем это грозит. Пустой раздел допустим, только если чек-лист покрыт полностью.
6. **Без правок.** Сабагенты пред-проверки и ревью ничего не меняют в репозитории (только читают и запускают
   проверки); правку делает тот, чья это роль (кодер, hardener, specifier).
7. **Остановка — по чек-листу.** Заканчивай, когда чек-лист покрыт и каждое утверждение доказано или помечено
   «не проверено», — а не когда нашёл первый ответ или «достаточно уверен».

Что это значит в Qwen Code:
- Qwen Code сам дописывает к промпту обычного сабагента «используй инструменты, только когда необходимо». Здесь
  необходимость задаёт чек-лист: каждый его пункт закрывается вызовом инструмента или идёт в «Не проверено».
- Команда, оборванная таймаутом (`Command timed out after …`), — не результат: её вывод неполон, гейт не зелёный.
- Длинный вывод Qwen Code обрезает, а сжатие контекста (`/compress`, авто при ~85 %) и очистка старых результатов
  инструментов после простоя убирают доказательства из разговора. Вывод Gradle пиши в файл и ищи в нём; после
  сжатия или перерыва повтори проверку, прежде чем на неё ссылаться. Пересказ — не доказательство.
- Прежние сообщения разговора, в том числе твои, — зацепки, а не факты: перепроверь у источника, прежде чем повторять.
- После долгой серии чтений и поиска подряд (около 100 вызовов) Qwen Code вставляет напоминание «this read-only
  exploration phase has reached the configured tool-call allowance … summarize the findings». Это не условие
  остановки: заканчиваешь по чек-листу. Если чек-лист ещё не покрыт, продолжай; что не успел, перечисли в
  «Не проверено» с причиной.

## 4. Отчёт сабагента и его приёмка
Формат отчёта каждого сабагента (роль добавляет к нему свой итог, например `VERDICT` ревьюера):
```
## Итог
<одна-две строки: ответ на вопрос задания>

## Проверено (покрытие: N из M по чек-листу)
1. <утверждение> — доказательство: `<команда>` → <вывод> | `<файл:строка>`: «<цитата>» | <URL, версия>: «<цитата>»
2. ...

## Не проверено
- <что> — <почему> — <чем грозит>

## Вопросы и риски для координатора
- ...
```
Приёмка (ты — в сессии задачи, координатор — в пред-проверке):
1. Утверждения без доказательств или нет раздела «Не проверено» — отчёт возвращается сабагенту с перечнем
   недостающего (доработка отчёта, не новый раунд работы; не больше двух возвратов, затем — «не проверено» и
   вопрос владельцу).
2. Минимум одно утверждение из каждого отчёта проверь сам тем же способом (команда, `файл:строка`, источник).
   Расхождение — отчёт не принят целиком, задача уходит другому сабагенту (новый вызов, не продолжение).
3. Утверждение, на котором держится решение, проверяет второй, независимый сабагент с задачей опровергнуть; ему не
   передают вывод первого — только вопрос и пути. При неуверенности — «опровергнуто».
4. В план, отчёт PR и промпт сессии утверждения идут с пометкой: «доказано (как)», «опровергнуто», «не проверено».

## 5. Перед словом «готово» (всегда; если Stop-хук не загружен — единственная опора)
1. Сам, на переднем плане, без параметра `timeout` короче прогона, из корня репозитория:
   `./gradlew gauntletFast --continue --console=plain > build/gauntlet-fast.log 2>&1; echo "exit=$?"`
   (в монорепо — в каждом модуле, где ход менял код: `cd core && ./gradlew … > build/gauntlet-fast.log 2>&1`, лог
   тогда `core/build/gauntlet-fast.log`).
2. `python3 gauntlet/hooks/stop_gate.py --verify-ran gauntletFast --log build/gauntlet-fast.log` (из корня, путь к
   логу — его) — код 0: Gradle выполнил каждую задачу гейта. Иначе прогон не считается, как бы ни выглядел вывод.
3. В отчёт — код выхода, строки `> Task …` каждой задачи гейта и итог:
   `grep -E '^> Task |BUILD (SUCCESSFUL|FAILED)|^gauntlet: ' build/gauntlet-fast.log`.
4. Финал (шаг 8 процесса) — так же для `./gradlew gauntlet --continue` (`--verify-ran gauntlet`).
5. Красный гейт или отказ `--verify-ran` — работа не сделана; так и напиши, с причинами. Решает CI.

## 6. Известные сбои Qwen Code и что ты делаешь
- **Фоновые сабагенты.** По умолчанию сабагент верхнего уровня уходит в фон, и его результат приходит позже
  уведомлением. Роли — только на переднем плане; результат фонового сабагента не предполагай, пока не пришло
  уведомление.
- **Таймаут оболочки.** Без настройки команда на переднем плане обрывается через 2 минуты, параметр `timeout`
  вызова — не больше 10 минут. В `.qwen/settings.json` таймаут поднят до 60 минут; не передавай свой `timeout`
  прогонам Gradle.
- **Хуки не загружены.** Без одобрения проектные хуки молча не работают (в `qwen -p` — одна строка в stderr).
  Признак — нет строки статуса (раздел 0).
- **Потолок Stop-хука.** Qwen Code отпускает после 8 блокировок подряд, набор — после 3. Отпущенный с красным
  гейтом — не «готово».
- **Без интерактива.** В `qwen -p` режимы Ask и Auto убирают оболочку и запись, если правило не разрешило их явно.
  Чего не смог запустить — «не проверено», а не вывод из чтения кода.
- **Напоминание «подведи итог».** На длинной серии одних чтений Qwen Code просит свернуть исследование (раздел 3).
  Покрытие чек-листа важнее: напоминание не разрешает ни остановиться раньше, ни писать файлы.
- **Переменные из `.env`.** Qwen Code при старте берёт переменные из `.qwen/.env` проекта и из `~/.env`, и они
  доходят до хуков набора. Не создавай и не правь такие файлы ради Qwen Code: охрана хуком и `permissions.deny`
  закрывает их, а выключать охрану (`GAUNTLET_GUARD`, `GAUNTLET_STOP_HOOK`) может только владелец.
