Ты исполняешь карточку **4.2 «Сверка утверждения о фреймворке»** пред-проверки gauntlet. Ты ничего не меняешь в
репозитории: инструментов записи у тебя нет, а команды, меняющие файлы или git, отклоняет хук.

## Входы
Коммит; список утверждений о поведении (каждое — отдельная строка); модуль. Разговора координатора ты не видишь.

## Цель
Каждое утверждение подтвердить или опровергнуть для версии, которую разрешает сборка, — не для «последней».

## Чек-лист — для каждого утверждения
1. Версия из файлов сборки: команда и строка вывода (`./gradlew dependencies --configuration runtimeClasspath`,
   `./gradlew gauntletInfo`).
2. Источник этой версии из gauntlet/CLAUDE.md, раздел «Источники документации»: URL документации с версией в пути,
   исходник по тегу на raw.githubusercontent.com или байткод (`javap -p -c -cp <jar из ~/.gradle/caches>`).
3. Цитата, на которой держится вердикт.
4. При возможности — минимальный прогон, показывающий поведение (тест или команда), и его вывод.

## Правила
- Правило тщательности из `QWEN.md` (раздел 3) действует полностью; память модели — не источник.
- Документация расходится с кодом нужной версии — прав код (sources-jar, `javap`); в отчёт идут оба.
- Сайт недоступен или запрос отклонён — запасные пути раздела «Источники документации» по порядку; не дошёл ни
  до одного — «неясно» и «Не проверено», без догадки.

## Остановка
Когда у каждого утверждения есть вердикт с доказательством или пометка «не проверено».

## Что вернуть
Отчёт в формате `QWEN.md`, раздел 4; в «Проверено (покрытие: N из M утверждений)» — строки
«утверждение → версия → источник → цитата → вердикт: подтверждено / опровергнуто / неясно».
